# 提炼标准

判断每一组话该不该收、收成什么、怎么写。动手判断前完整读一遍，拿不准时回来查。

## 总原则

1. **大多数对话是一次性的。** 用户要的是"以后还会用"的东西，不是对话摘要。宁可漏掉，也不要把一次性的提示词收进来。几百个对话通常只提炼出 5–30 条；超过 50 条，多半收得太松。
2. **每条候选都要答得出："用户下次什么时候会再用它？"** 答不出就不收。
3. **只用用户自己说过的话。** 模板和规则里的每个要求，都要能在原话里找到出处。不替用户补充没说过的要求，不把 AI 的回答当成用户的提示词，不改成"标准提示词"的腔调。
4. **隐私优先。** 密钥、密码、Token、手机号、邮箱、身份证号、住址、公司内部链接，一律不写进候选；原话证据里出现时换成 `[已隐藏]`。

## 第一步：先排除一次性的

下面这些不收，哪怕出现很多次、写得很长：

| 情况 | 例子 | 为什么不收 |
|---|---|---|
| 针对具体对象的任务 | 「把 src/App.tsx 的列表改成三栏」「这个报错怎么回事：TypeError…」「分析一下这份 3 月的销售表」 | 对象换了就用不上 |
| 同一个对话里的来回修改 | 一个对话里说了 5 次「再短点」「换个说法」 | 说明这次没改好，不说明是习惯 |
| 太短、重打一遍不费事的 | 「继续」「好的」「提交一下」「跑一下测试」「用方案二」 | 存了也不会去复制 |
| 知识性提问 | 「什么是向量数据库」「React 和 Vue 哪个好」 | 问题本身就是一次性的；除非用户反复用同一个固定格式提问 |
| 回答 AI 的提问 | 「对，用第二种」「路径是 /tmp」 | 只在那个上下文里有意义 |
| 自动注入和贴进来的材料 | 系统提示、环境信息、规则文件、工具输出、粘贴的文档和代码 | 不是用户写的提示词 |
| 已经存在的 | 已写在 AGENTS.md、CLAUDE.md、记忆文件、Skill 里的规则；PromptBox 库里已有的提示词 | 重复 |
| 前后矛盾或被推翻的 | 有时要「详细点」、有时要「简短点」，又分不出场景 | 收了反而误导 |
| 某个项目某段时间的临时安排 | 「这周先别管样式」「今天只改后端」 | 过几天就失效 |

## 第二步：判断值不值得收

### 提示词：做某类事的方法，用的时候复制

三条**同时满足**才收：

1. **会重复**：同一类任务出现**至少 3 次**，分布在**至少 2 个不同的对话**、**至少 2 个不同的日子**里。每次处理的材料不同，但要求基本一样。
   - 只看次数不够：一天里重试 5 次同一件事，不算重复。
   - 字面不同、意思相同的算同一类：「改成小红书风格」「写成小红书的样子」「小红书风格改写一下」。
2. **值得存**：重新写一遍要费心思。满足任一：有角色、步骤、格式、字数、语气这类具体要求；或者用户每次做完都要补同样的要求（比如「控制在 200 字」）。
   - 只有一句「帮我总结一下」「翻译一下」，不收。
3. **能通用**：把每次不一样的部分换成 `{{变量}}` 以后，剩下的话放到以后的新材料上照样适用，没有残留的具体文件名、人名、日期、数字。

### 规则：希望 AI 一直遵守的习惯

满足**任一条**就收：

1. **明确说了要长期遵守**：原话里有「以后」「今后」「每次」「一直」「始终」「默认」「记住」「都这样」「不要再」这类词，而且内容是稳定的习惯，不是针对眼前这件事。出现 1 次就可以收，理由写「明确要求」。
   - 收：「以后回答都先给结论」「记住，不要用 emoji」
   - 不收：「以后这个函数都用 async」（只对这段代码）、「今天以后的会议都发我」（不是对 AI 的要求）
2. **反复纠正**：同一个要求出现**至少 3 次**，分布在**至少 2 个不同的对话**里，而且跟在**不同的任务**后面。
   - 只跟在同一类任务后面的，是那个任务的要求，写进那条提示词模板，不单独成为规则。
3. **反复主动交代**：用户在开始任务时，习惯性地附上同样的约束（比如每次都写「用中文、别用表情」），同样按至少 3 次、2 个对话计算。

### 拿不准的

- 只出现 2 次、或只在一个对话里出现的：不收，除非是「明确要求」。
- **只出现过 1 次、但写得很完整的长提示词**：有角色、多条要求、输出格式，而且没有具体对象，明显能反复用。可以收，置信度标「中」，理由写「只出现 1 次，但结构完整、可以通用」。每次最多收 5 条这种。
- 同一个项目里反复出现的项目约定（「这个项目用 pnpm」「组件放 src/components」）：收成规则，适用范围标这个项目。

## 第三步：分类

每条候选都标下面几项。

| 字段 | 取值 | 说明 |
|---|---|---|
| 类型 `type` | `prompt` 提示词 / `rule` 规则 | |
| 主题标签 `tags` | 1–2 个：写作、编程、产品、设计、数据分析、翻译、学习、办公、生活、其他 | 用户在 PromptBox 里已有标签的，优先沿用 |
| 适用范围 `scope` | `global` 所有对话 / `project` 某个项目 / `task` 某类任务 | 只有规则需要，而且必须写；提示词不分范围。项目写 `project` 字段（项目名或完整路径）；某类任务写 `taskType`（比如「写代码」「写文章」） |
| 规则类别 `ruleCategory` | 语言、篇幅、格式和结构、语气和风格、工作流程、代码规范、工具和环境、安全和隐私 | 只有规则需要 |
| 导出建议 `export` | 提示词默认 `md`；多步骤、在 Agent 里执行的工作流程建议 `skill`，并给英文短名和描述；规则默认 `agents` | |

判断规则适用范围的办法：

- 跟在各种不同任务后面都出现过的 → `global`
- 只在某个项目的对话里出现（看对话的工作目录、提到的技术栈和路径）→ `project`
- 只在某类任务里出现（比如只在写代码时说「注释用中文」）→ `task`

## 第四步：怎么写

### 名称 `title`

6–12 个字，说清做什么：「小红书风格改写」「周报整理」「先给结论再给理由」。不要写「提示词 1」「写作助手」。

### 提示词模板 `content`

- 从最常见、最完整的那一次改写，保留用户自己的说法。
- 每次不一样的部分换成 `{{变量}}`，变量名用简短中文：`{{内容}}`、`{{主题}}`、`{{代码}}`、`{{竞品列表}}`。同一个变量在模板里多次出现时用同一个名字。
- 用户常在做完之后补充的要求（比如 6 次里有 4 次补了「控制在 200 字」），合并进模板，并写进 `fixes`。
- 不加原话里没有的要求。可以整理顺序、合并重复，但不要扩写。

### 规则 `content`

- 一条只说一件事，写成能直接放进 AGENTS.md 的一句话：「回答使用中文。」「先给结论，再给理由。」
- 同一个意思的不同说法合并成一条：「说中文」「中文回答」「用中文讲」→「回答使用中文。」

### 理由 `reason`

一句话说明为什么值得存，带上关键数字：

- 「过去 3 周里 6 次让 AI 改写小红书文案，每次内容不同，其中 4 次补了字数要求」
- 「在 Codex 和 Claude Code 的 9 个对话里纠正过 12 次」
- 「明确要求：以后回答都先给结论」

### 置信度 `confidence`

- `high`：重复 5 次以上，或「明确要求」。
- `medium`：重复 3–4 次，或「结构完整的单次长提示词」。
- 达不到 `medium` 的不收。

### 原话证据 `quotes`

3–5 句，挑最有代表性、说法不同的。每句不超过 120 个字，隐私换成 `[已隐藏]`。紧跟着的纠正写进 `after`。

## 第五步：自查

写完逐条过一遍：

- [ ] 这条下次会在什么时候用？说得出来吗？
- [ ] 模板里还有没有具体的文件名、人名、日期、数字、报错信息？
- [ ] 有没有替用户编了要求？
- [ ] 和别的候选、和已有的规则文件重复吗？
- [ ] 原话证据里还有没有隐私？
- [ ] 总数合理吗？

## 例子

### 收

原话（3 个不同的日子、3 个对话）：

> 把下面这段改成小红书风格：周末去了一家咖啡店…… → 之后：太长了，控制在 200 字
> 帮我把这段写成小红书的风格：新买的跑鞋…… → 之后：太长了，200 字以内
> 改成小红书风格，多用短句：这次去杭州玩了三天……

候选：

```json
{
  "type": "prompt",
  "title": "小红书风格改写",
  "content": "把下面这段改成小红书风格，多用短句，控制在 200 字：\n{{内容}}",
  "tags": ["写作"],
  "scope": "global",
  "fixes": ["控制在 200 字"],
  "reason": "3 个不同的日子里让 AI 改写小红书文案，每次内容不同，其中 2 次补了字数要求",
  "confidence": "medium"
}
```

### 不收

> 帮我看看这个报错：Cannot read properties of undefined (reading 'map')（出现 4 次，都在同一个对话里）

一次性：针对具体报错，而且只在一个对话里。

> 总结一下（出现 20 次）

太短，重打一遍不费事；也没有具体要求。如果用户每次总结后都补「用三点列出来」，那么「用三点列出来」可能是一条规则，「总结一下」本身不收。
