# PromptBox

从你和 AI 的对话里提炼提示词和规则，再按你自己的风格写新的。

库和扫描记录保存在当前浏览器。浏览器本地扫描不上传聊天记录；用模型生成、AI 提炼或让外部 Agent 提炼时，相关内容会发送给你选用的模型。

## 三种方式把提示词收进来

### 1. 自己存

- 点「新建」写一条，或者把 `.md`、`SKILL.md`、`AGENTS.md`、`CLAUDE.md` 拖进窗口。
- 两种类型：**提示词**（做某件事的方法，用的时候复制）和**规则**（希望 AI 一直遵守的习惯）。
- 不用点保存，改了自动保存。离开一条内容时，正文改过就存一个版本；点「历史」可以对比任意两个版本，也可以恢复旧版本，恢复本身也会存成新版本，历史不会丢。
- 规则可以指定适用范围：所有任务、某个项目或某类任务。提示词不分范围。没写范围的旧规则按所有任务处理。

### 2. 扫描以前的对话，可以再交给模型提炼

1. 在「发现」里点「管理记录来源」，添加 Codex、Claude Code、WorkBuddy 的本地记录，或 ChatGPT、Claude 网页版导出的 `conversations.json`。
2. PromptBox 在浏览器里扫描，找出你反复交代的任务和反复做的纠正，候选出现在「发现」里，附原话证据。这一步不调用模型。
3. 在「设置」里填了模型 Key 后，可以点「AI 提炼」：把分好组的原话（每组几句，每句最多 200 字）交给模型，按和本地 Agent 同一份提炼标准再筛一遍，判断哪些是一次性的，起好名字，写成模板或规则。不发送完整聊天记录。
4. 逐条确认、修改或忽略。和库里相似的会合并进那一条；规则保存前要确认适用范围。模型判断为一次性的会收起来，可以展开再看。

### 3. 让本地 Agent 提炼

1. 在「发现」→「管理记录来源」里点「下载 Skill」，把解压出的 `promptbox-extract` 文件夹放进 Agent 的技能目录：Claude Code 是 `~/.claude/skills/`，Codex 是 `~/.codex/skills/`，WorkBuddy 是 `~/.workbuddy/skills/`。仓库里的原文件在 [`skills/promptbox-extract/`](skills/promptbox-extract/)。
2. 对 Agent 说：「用 promptbox-extract 技能，帮我从聊天记录里提炼值得长期保存的提示词和规则，一次性的不要。」
3. Agent 会先说明要读哪些记录、等你确认，再写出 `promptbox-candidates-日期.json`。把它拖进 PromptBox，候选出现在「发现」里，附上保存理由、把握程度和适用范围，逐条确认。

Skill 的采集脚本支持 Codex、Claude Code、WorkBuddy、CodeBuddy 和网页版导出，还能读 Codex 压缩过的旧会话（需要本机有 `zstd` 命令）；其他工具由 Agent 按 Skill 里的方法识别。Agent 提炼时，记录会进入它所用模型的上下文。

## 收进来之后

- **搜索**：输入关键词，或者直接写一句需求。
- **复制**：正文里有 `{{变量}}` 时逐个填写，实时预览。复制出去的就是正文本身。
- **按我的风格生成**：搜索框里写一句需求，参考库里相关的提示词和规则，生成一条新的。所有任务的规则每次都会参考；参考的提示词带着某类任务的标签时，这类任务的规则也会带上；选了项目或任务，再加上这个范围的规则。没填 Key 时可以复制生成指令，在常用 AI 里生成后粘回来。
- **导出**：单条导出成 `.md` 或 `SKILL.md`；全部规则合成一份 `AGENTS.md` 或 `CLAUDE.md`，限定了项目或任务的规则按范围分组，写明只在这个范围里适用。
- **备份**：一键导出全部内容，换浏览器时再导入。

第一次打开时内置 8 条示例和 33 段示例对话，可以先体验主要流程。

## 本地提炼是怎么做的

不调用模型，全部在浏览器里计算：

1. **读取**：在后台线程里解析各工具的记录格式，去掉工具调用、环境信息、规则文件这类自动注入的内容。再次扫描时只读新增和改动过的文件。Codex 压缩过的旧会话（`.jsonl.zst`）浏览器读不了，会跳过并提示数量。
2. **分类**：每段对话的第一句和像在下指令的句子算"任务"；紧跟在 AI 回答后面、又在提要求的短句算"纠正"。
3. **找重复**：任务按"指令部分"（冒号或换行之前）的相似度归类，比较时用两个字一组的切片，不依赖分词词典。纠正先归到常见说法（用中文、先给结论、不用套话……），其余按相似度归类。
4. **生成候选**：出现 3 次以上、来自 2 个以上对话的，才成为候选。每次不一样的部分变成 `{{变量}}`；常在之后补的要求（比如"控制在 200 字"）合并进模板，界面上用下划线标出。
5. **对照**：和库里相似的标出来，保存时合并进那一条；规则只在选定的范围和那一条一致时才合并。保存或忽略过的，下次扫描不再出现；规则只在同一个范围里认，忽略了项目 A 的规则不会藏起项目 B 的。

## 隐私

- 浏览器本地扫描只在本地计算，扫描读到的句子保存在当前浏览器的数据库里。
- 只有点了模型生成、AI 提炼或连接测试时才会请求模型：生成发送需求和勾选的参考内容；AI 提炼发送分好组的原话，每句最多 200 字，开始前会告诉你发送多少。Key 保存在当前浏览器，请求直接发给服务商。外部 Agent 提炼遵循该 Agent 的模型和数据设置。
- 备份包含库内容、处理记录和正文版本。已保存条目的原话证据也会备份，但不包含整个扫描记录库。
- 换浏览器、清除浏览器数据时，数据不会跟着走，记得定期导出备份。

## 快速开始

需要 Node.js 22.12 或以上。

```bash
npm install
npm run dev
```

用 Chrome 或 Edge 打开终端里显示的地址。

### 记录来源

| 来源 | 选什么 |
|---|---|
| Codex | `~/.codex/sessions` 文件夹（里面的 `rollout-*.jsonl`） |
| Claude Code | `~/.claude/projects` 文件夹（里面的 `*.jsonl`） |
| WorkBuddy | `~/.workbuddy/projects` 文件夹（里面的 `*.jsonl`） |
| ChatGPT、Claude 网页版 | 在网页版设置里导出数据，选择解压后的 `conversations.json` |

在 macOS 的选择窗口里按 `⌘⇧.` 可以显示以点开头的隐藏文件夹。Chrome 和 Edge 会记住文件夹授权，之后点刷新按钮只扫描新增的对话；其他浏览器每次扫描都要重新选择文件夹。

### 模型服务

在「设置」里选择服务商，填 API Key 和模型。支持兼容 OpenAI 接口、并且允许网页直接调用的服务：

- OpenAI、DeepSeek、通义千问、智谱
- 其他兼容 OpenAI 接口的服务（自己填接口地址）

能否连接取决于服务商的跨域策略、接口地址和账户权限，以连接测试为准。当前界面未预设 Kimi。

## 开发

```bash
npm run dev        # 开发服务器
npm test           # 单元测试（Vitest）
python3 -m unittest discover -s skills/tests  # Skill 脚本测试，使用合成记录
npm run typecheck  # 类型检查
npm run build      # 类型检查 + 生产构建，输出到 dist/
```

技术栈：Vite、React、TypeScript、Dexie（浏览器本地数据库）、Vitest。纯前端，没有后端和登录。

### 目录结构

```
src/
├── logic/            纯函数，大部分有单元测试
│   ├── discover/     提炼引擎：解析记录、分类、找重复、生成候选
│   ├── search.ts     关键词检索
│   ├── generate.ts   挑参考、拼生成指令
│   ├── llm.ts        调用兼容 OpenAI 接口的模型
│   ├── refine.ts     AI 提炼：和 Skill 共用 rubric.md 提炼标准
│   ├── scope.ts      规则的适用范围
│   ├── diff.ts       版本对比
│   ├── zip.ts        打包下载 Skill
│   ├── exporters.ts  导出格式（SKILL.md 字段按 Anthropic 文档校验）
│   └── importers.ts  导入识别、备份格式
├── scan/             后台扫描线程和文件夹授权
├── db/               本地数据库和所有写操作
├── components/       界面：侧栏、列表、详情、各个弹窗
├── samples/          示例库和示例对话
└── App.tsx           三栏布局和状态
skills/
├── promptbox-extract/  给本地 Agent 用的提炼 Skill：流程、提炼标准、记录位置、候选文件格式、采集和检查脚本
└── tests/              Skill 脚本的测试，用合成记录
docs/                 PRD、产品框架、竞品调研、可点击原型、立项报告
```
