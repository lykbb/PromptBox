# PromptBox

从你和 AI 的对话里提炼提示词和规则，再按你自己的风格写新的。

库和扫描记录保存在本机：桌面版使用应用自己的存储，网页版使用当前浏览器。本地扫描不上传聊天记录；用模型生成、问 AI 或让外部 Agent 提炼时，相关内容会发送给你选用的模型。

## 三种方式把提示词收进来

### 1. 自己存

- 点「新建」写一条，或者把 `.md`、`SKILL.md`、`AGENTS.md`、`CLAUDE.md` 拖进窗口（也可以在「设置」→「记录来源」里选择文件）。
- 两种类型：**提示词**（做某件事的方法，用的时候复制）和**规则**（希望 AI 一直遵守的习惯）。
- 不用点保存，改了自动保存。离开一条内容时，正文改过就存一个版本；点「历史」可以对比任意两个版本，也可以恢复旧版本，恢复本身也会存成新版本，历史不会丢。
- 规则可以指定适用范围：所有任务、某个项目或某类任务。提示词不分范围。没写范围的旧规则按所有任务处理。

### 2. 扫描以前的对话，可以再交给模型提炼

1. 在「设置」→「记录来源」里连接 Codex、Claude Code、WorkBuddy 的记录文件夹，或者把 ChatGPT、Claude 网页版导出的 .zip 直接拖进来（两家的导出分开保留，同一家再导出一次会替换旧的）。之后点「发现」标题旁的刷新按钮，只扫描新增的对话。
2. PromptBox 在浏览器里扫描，找出你反复交代的任务和反复做的纠正，候选出现在「发现」里，附原话证据。这一步不调用模型。
3. 拿不准的候选，打开它点标题右边的 ✦ 图标，让 AI 看看这条（要先在「设置」里填好模型 Key）：只把这一条的几句原话（每句最多 200 字）发给模型，按和本地 Agent 同一份提炼标准判断。AI 的意见显示在这条下面：值得留的给出建议的名称和写法，一次性的或和别的重复的写明原因。用 AI 的版本还是保持原样由你决定，可以撤回，不会多冒出新的候选。候选很多时，可以在「设置」→「AI 模型」里一次让 AI 看完全部候选，结果同样挂在各条下面。
4. 逐条确认、修改或忽略。和库里相似的会合并进那一条；规则保存前要确认适用范围。

### 3. 让本地 Agent 提炼

1. 在「设置」→「记录来源」里点「下载 Skill」，把解压出的 `promptbox-extract` 文件夹放进 Agent 的技能目录：Claude Code 是 `~/.claude/skills/`，Codex 是 `~/.codex/skills/`，WorkBuddy 是 `~/.workbuddy/skills/`。仓库里的原文件在 [`skills/promptbox-extract/`](skills/promptbox-extract/)。
2. 对 Agent 说：「用 promptbox-extract 技能，帮我从聊天记录里提炼值得长期保存的提示词和规则，一次性的不要。」
3. Agent 会先说明要读哪些记录、等你确认，再写出 `promptbox-candidates-日期.json`。把它拖进 PromptBox，候选出现在「发现」里，附上保存理由、把握程度和适用范围，逐条确认。

Skill 的采集脚本支持 Codex、Claude Code、WorkBuddy、CodeBuddy 和网页版导出，还能读 Codex 压缩过的旧会话（需要本机有 `zstd` 命令）；其他工具由 Agent 按 Skill 里的方法识别。Agent 提炼时，记录会进入它所用模型的上下文。

## 收进来之后

- **搜索**：输入关键词，或者直接写一句需求。
- **复制**：正文里有 `{{变量}}` 时逐个填写，实时预览。复制出去的就是正文本身。
- **按我的风格生成**：搜索框里写一句需求，参考库里相关的提示词和规则，生成一条新的。所有任务的规则每次都会参考；参考的提示词带着某类任务的标签时，这类任务的规则也会带上；选了项目或任务，再加上这个范围的规则。没填 Key 时可以复制生成指令，在常用 AI 里生成后粘回来。
- **导出**：单条导出成 `.md` 或 `SKILL.md`；全部规则合成一份 `AGENTS.md` 或 `CLAUDE.md`，限定了项目或任务的规则按范围分组，写明只在这个范围里适用。
- **备份**：在「设置」→「数据」里一键导出全部内容，换浏览器时把备份文件拖进来就能恢复。
- **外观**：在「设置」→「外观」里选主题色（黑白灰、纸张、海蓝、森林、暮紫）和明暗（浅色、深色、跟随系统）；侧栏底部的开关可以一键切换深色。

第一次打开时内置 8 条示例和 33 段示例对话，可以先体验主要流程。

## 本地提炼是怎么做的

不调用模型，全部在浏览器里计算：

1. **读取**：在后台线程里解析各工具的记录格式，去掉工具调用、环境信息、规则文件这类自动注入的内容。再次扫描时只读新增和改动过的文件。Codex 压缩过的旧会话（`.jsonl.zst`）浏览器读不了，会跳过并提示数量。
2. **分类**：每段对话的第一句和像在下指令的句子算"任务"；紧跟在 AI 回答后面、又在提要求的短句算"纠正"。
3. **找重复**：任务按"指令部分"（冒号或换行之前）的相似度归类，比较时用两个字一组的切片，不依赖分词词典。纠正先归到常见说法（用中文、先给结论、不用套话……），其余按相似度归类。
4. **生成候选**：出现 3 次以上、来自 2 个以上对话的，才成为候选。每次不一样的部分变成 `{{变量}}`；常在之后补的要求（比如"控制在 200 字"）合并进模板，界面上用下划线标出。
5. **对照**：和库里相似的标出来，保存时合并进那一条；规则只在选定的范围和那一条一致时才合并。保存或忽略过的，下次扫描不再出现；规则只在同一个范围里认，忽略了项目 A 的规则不会藏起项目 B 的。

## 隐私

- 浏览器本地扫描只在本地计算，扫描读到的句子保存在当前浏览器的数据库里。
- 只有点了模型生成、问 AI 或连接测试时才会请求模型：生成发送需求和勾选的参考内容；问 AI 只发送那几条候选的原话，每句最多 200 字，一次问完前会列出要发哪几条。Key 保存在当前浏览器，请求直接发给服务商。外部 Agent 提炼遵循该 Agent 的模型和数据设置。
- 备份包含库内容、处理记录和正文版本。已保存条目的原话证据也会备份，但不包含整个扫描记录库。
- 换浏览器、清除浏览器数据时，数据不会跟着走，记得定期导出备份。

## 快速开始

需要 Node.js 22.12 或以上。

```bash
npm install
npm run dev
```

用 Chrome 或 Edge 打开终端里显示的地址。

### 桌面版（macOS）

v0.2.0 起是独立的 macOS 应用：Swift/AppKit 管理窗口、系统菜单和本机操作，WKWebView 复用现有界面。运行不依赖 Chrome、Python、Node 或 Electron。支持 Apple Silicon、macOS 14 及以上。

已打包版本见 [GitHub Releases](https://github.com/lykbb/PromptBox/releases/latest)，下载 `PromptBox-macOS-0.2.1-arm64.dmg`，打开后将 `PromptBox.app` 拖进 Applications，再从「应用程序」打开。

也可以自行打包：

```bash
npm run package:mac
```

生成 `release/PromptBox-Desktop-v0.2.1/PromptBox.app` 和 `release/PromptBox-macOS-0.2.1-arm64.dmg`，不生成额外过程记录或校验文件。已有产物默认拒绝覆盖。当前为本机临时签名，未做 Developer ID 签名和 Apple 公证，DMG 格式不会免除 macOS 安全检查。确认从可信来源下载后，首次受阻可按 [Apple 官方说明](https://support.apple.com/102445)在「系统设置 → 隐私与安全性 → 仍要打开」单独允许；不需要关闭系统安全检查。

桌面版不带示例。从源码项目运行时，数据统一放在项目根目录的 `data/` 中：`library.json` 保存内容、版本、扫描记录和设置，`library.previous.json` 保留上一次写入，`folders.json` 保存文件夹授权路径。WebKit 只保留临时工作数据，不使用浏览器的持久数据库。此目录可能含 Key 和原话证据，已排除 Git 上传；请用「设置 → 数据」导出备份，避免直接修改库文件。单独下载安装的应用会使用用户「文稿」里的 `PromptBox/` 文件夹，避免向只读的 DMG、Applications 或系统隔离目录写数据；如果旧版应用旁已有可写的 `PromptBox Data/library.json`，继续原地使用，不自动迁移或导入。

旧版 Chrome 数据不会自动迁移，模型 Key 也需要重新填写；文件菜单的「打开旧版浏览器数据」可回到原来源导出备份。移动新版应用或项目时，请同时保留对应数据文件夹。

原生进程内的只读资源服务监听 `127.0.0.1:53917`，为界面模块、数据库和扫描线程提供稳定的本地来源；不提供数据或原生调用接口。退出 PromptBox 时服务随进程结束，没有独立的 Python 后台进程。被其他程序占用时会明确报错，避免打开错误服务。

桌面版支持系统文件打开和保存面板、文件夹授权与增量扫描、剪贴板及模型请求。模型请求通过原生网络层发送，不受网页跨域限制。开发入口为 `npm run desktop:run`，原生部分见 [`desktop/README.md`](desktop/README.md)。

### 记录来源

| 来源 | 选什么 |
|---|---|
| Codex | `~/.codex/sessions` 文件夹（里面的 `rollout-*.jsonl`） |
| Claude Code | `~/.claude/projects` 文件夹（里面的 `*.jsonl`） |
| WorkBuddy | `~/.workbuddy/projects` 文件夹（里面的 `*.jsonl`） |
| ChatGPT、Claude 网页版 | 在网页版设置里申请导出数据，把邮件里下载的 .zip 直接拖进来；两家都没有可以授权读取聊天记录的接口 |

这些文件夹以点开头，选择窗口里默认看不到：在「记录来源」里点「复制路径」，打开选择窗口后按 `⌘⇧G`（Windows 在地址栏，Linux 按 `Ctrl+L`）粘贴。Chrome 和 Edge 会记住文件夹授权，之后点刷新按钮只扫描新增的对话；其他浏览器每次扫描都要重新选择文件夹。

### 模型服务

在「设置」→「AI 模型」里选服务商、粘贴 API Key，PromptBox 会自动读取这个 Key 能用的模型，从下拉列表里选或输入搜索；读不到时点模型旁边的刷新按钮重试，点「测试一下」确认能连上。每家服务商的 Key 分别记住，切换时自动恢复；用过的模型都列在这一页最上面，点一下就能换。预设了这些允许网页直接调用的服务：

- 国内：DeepSeek、通义千问（阿里云百炼）、智谱 GLM、Kimi、豆包（火山方舟）、硅基流动、MiniMax、百度千帆、阶跃星辰、魔搭 ModelScope
- 国外：OpenAI、Anthropic Claude、Google Gemini、xAI Grok、Mistral、Groq、OpenRouter
- 自己添加的兼容 OpenAI 接口：填接口地址和 Key，添加过的都会记住，以后在服务商下拉框里直接选。服务端要开启跨域（CORS），并且预检请求（OPTIONS）不能要求 Key

火山方舟不提供模型列表，需要手动填 Model ID 或接入点 ID。xAI、硅基流动、百度千帆的跨域设置在 Firefox、Safari 里可能被拦，建议用 Chrome 或 Edge。腾讯混元不允许网页直接调用，所以没有预设。

## 开发

```bash
npm run dev        # 开发服务器
npm test           # 单元测试（Vitest）
python3 -m unittest discover -s skills/tests  # Skill 脚本测试，使用合成记录
npm run typecheck  # 类型检查
npm run build      # 类型检查 + 生产构建，输出到 dist/
```

技术栈：Vite、React、TypeScript、Dexie（浏览器本地数据库）、Vitest。纯前端，没有后端和登录。

### 目录结构

```
src/
├── logic/            纯函数，大部分有单元测试
│   ├── discover/     提炼引擎：解析记录、分类、找重复、生成候选
│   ├── search.ts     关键词检索
│   ├── generate.ts   挑参考、拼生成指令
│   ├── llm.ts        调用兼容 OpenAI 接口的模型
│   ├── refine.ts     问 AI：和 Skill 共用 rubric.md 提炼标准，结果变成每条候选下的意见
│   ├── scope.ts      规则的适用范围
│   ├── diff.ts       版本对比
│   ├── zip.ts        打包下载 Skill
│   ├── unzip.ts      在浏览器里读 zip，网页版导出不用先解压
│   ├── chatExport.ts 认出 ChatGPT、Claude 的聊天记录导出
│   ├── exporters.ts  导出格式（SKILL.md 字段按 Anthropic 文档校验）
│   └── importers.ts  导入识别、备份格式
├── scan/             后台扫描线程和文件夹授权
├── db/               本地数据库和所有写操作
├── components/       界面：侧栏、列表、详情、各个弹窗
├── samples/          示例库和示例对话
└── App.tsx           三栏布局和状态
skills/
├── promptbox-extract/  给本地 Agent 用的提炼 Skill：流程、提炼标准、记录位置、候选文件格式、采集和检查脚本
└── tests/              Skill 脚本的测试，用合成记录
docs/                 PRD、产品框架、竞品调研、可点击原型、立项报告
```
